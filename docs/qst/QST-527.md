# QST-527 Arc確認質問とQuest文脈の整合

## 管理情報

- Priority: P0 / High（初回価値の阻害）
- Status: In Progress / ローカル実装・実機とHosted検証待ち
- 対応Finding: LA-02、LA-03
- 根拠: `reports/qst/LAUNCH_RETENTION_AUDIT_20260930.md`
- 上位原則: Master Spec v2.1、Design Bible v2「Quest Intent Confirmation」

## 背景とユーザー問題

現行の旅行相談では「シンガポールに行きたい」から5問を順に聞く。Design Bibleの最大3問と衝突し、既に明確な願いでも初回行動まで遠い。回答後のQuest詳細には質問文を含む生の会話要約と「航路条件」が重複表示され、条件が読み取れる成果・制約ではなく長い本文になる。

## 目的と範囲

Arcの質問を航路・安全・成功条件を変える最大3問へ絞り、答えを構造化された計画文脈として保存・表示する。明確な願いは質問を省略できる。対象は `quest_clarification_service.dart`、`arc_quest_clarification_session.dart`、`arc_screen.dart`、Quest提案とQuest詳細の表示、関連するWidget/Domainテスト。AI生成品質全体、Mission生成器、DBの大規模再設計、Guild、課金は対象外。

## 既存QSTとの関係・依存

- QST-260/266/267のUI・日本語規約を維持する。QST-261の最初のTask導線を妨げない。
- QST-250/252の構造化出力と整合し、QST-256の固定評価で回帰を検出する。
- 新しい保存契約が必要なら、まず既存Questの読み込み互換とMigration要否を別途評価する。旧本文の一括書き換えはしない。

## UI/UX・日本語・Accessibility

- 最初の提案には「Arcが理解したQuest」「確認が必要な点」を短く表示し、理由のない質問を追加しない。
- 質問は合計0〜3問。本人が「後で決める」を選べる条件は強要しない。安全上必須の確認は理由を明示する。
- Quest詳細では期限、同行者、予算、関心、旅行スタイルをラベル付きで必要なものだけ表示し、質問文や同じ見出しを重複させない。
- アクセシビリティ読み上げは `条件名 → 値`、編集ボタンは対象条件を明示する。200%文字拡大でも折り返しと焦点移動を保つ。
- 既存の希望年月は本人の値として維持し、月初日を勝手に「希望日」として見せない。

## データ・AI・Security

- 受け取った事実は `type/value/source/confirmed_at` 相当の型付き条件として扱い、Quest本文へ質問文を足し込まない。旧データは読み取り時に安全に表示する。
- 推測値と本人確認済みの値を区別する。Geminiが利用できない場合、固定の5問へ退避しない。本人の入力を保持し、手動で続けられる。
- 未同意の会話全文を計画・計測・検索クエリへ送らない。分析イベントは質問数・完了/離脱・条件種別の粗い値のみで、回答本文を記録しない。
- owner/RLSの境界を変えず、過去Questの条件を別アカウントへ露出させない。

## Analytics

`arc_clarification_started/answered/skipped/completed`、`quest_context_confirmed`を機微情報なしで定義する。分母は同意後にQuest化導線へ進んだユニークユーザー、同一session/idempotency keyの重複を除外する。質問数別の初回Task到達率を比較し、Arc提案の採用率だけを最適化しない。

## 受入条件

- 正常系: 旅行・学習・習慣・既に具体的な願いの固定ケースで0〜3問となり、Quest確認前に本人が編集できる。Quest詳細に「航路条件」は1回以下、質問文の羅列はない。期限・予算などがMission Planningへ型付きで引き継がれる。
- 失敗系: AI/通信失敗時は回答済み条件を失わず、再試行か手動作成を選べる。旧Questは欠損なく表示できる。
- Negative: 5問の旅行固定列、重複見出し、明確な願いへの無意味な質問、回答本文のanalytics記録、他人の条件参照を拒否する。
- Responsive/Localization: 320/360/390/430px、文字拡大200%、日本語IME、英語表示でCTA・条件値が切れない。
- 性能: 質問選択・条件表示は既存画面の表示予算を悪化させず、追加Gemini呼び出しを必須にしない。

## テスト・段階公開・Rollback

- Domain/Widget: 質問上限、明確な願い、期限既入力、同一条件の二重挿入、旧データ、AI失敗、owner切替、IME、Semanticsを追加する。
- Web/Android E2E: Arc相談→0〜3問→Quest確認→再起動→条件表示。current-SHAのスクリーンショットを添付する。
- Feature flag `arc_quest_context_v2` で内部先行。旧方式への単純な再有効化は最大3問と重複防止を満たさないので、Rollbackは「構造化条件表示を隠して編集可能な安全な要約を表示」に限定する。
- 完了証跡: テスト結果、before/after画像、互換データfixture、AI評価コーパス、owner境界確認、使用SHA。
- 残余リスク: AIによる意味の取り違え、旧自由文の条件抽出誤り、複数Questでの条件流用。本人確認と保守的な移行で抑える。
