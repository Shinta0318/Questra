## Finding

The local `auth-login` function classified only `invalid_credentials`, rate limits, and 5xx responses. Any other non-OK Supabase Auth response fell through to the public wrong-credentials response. An upstream error without a recognized code could therefore be misreported as a bad ID/password. The deployed Beta function is older still and has not been changed by this QST. This finding does not establish why the account owner's login failed.

## Change

- `invalid_credentials` remains the only Supabase Auth result that increments Questra's failed-login counter.
- `email_not_confirmed` uses the same generic public 401 response as invalid credentials without incrementing the counter. Existing login-screen confirmation help remains available; the response does not reveal account state.
- Rate limits remain 429. Unknown Auth failures now fail closed with 503 rather than claiming the user supplied a wrong password. The Flutter client already maps this to a retry-later service message.
- Authentication specification and focused Node/Flutter tests now cover the distinction. The status and upstream body are not logged with credentials or personal data.

## Verification

- `node --test supabase/functions/auth-login/*.test.mjs`: 12 passed.
- `flutter test --no-pub test/auth_login_function_error_test.dart`: 5 passed.
- The test set proves classifier and user-feedback behavior. It does not execute the Deno `index.ts` handler against Hosted Auth. `deno check` and same-candidate Hosted E2E remain unrun on this Windows host.
- Supabase's [Auth error-code reference](https://supabase.com/docs/guides/auth/debugging/error-codes), checked 2026-10-18, distinguishes `invalid_credentials`, `email_not_confirmed`, rate limits, and server errors. Its guidance is not evidence that the current Hosted Questra function uses this source.

## Rollback and residual risk

Reverting the classifier and handler branches restores the previous mapping; no migration or data rewrite is involved. The Beta `auth-login` function still needs a reviewed immutable candidate deployment and a safe real-account or disposable-account login test. Account mapping and password-hash presence cannot prove password correctness. QST-569/570 release gates remain open, and External Beta remains NO-GO.
