## Change

The existing `void` counter functions cannot tell the Edge Function whether a row was updated. A new, additive migration defines service-role-only v2 functions returning `recorded`, `locked`, or `missing`. Each decision locks the account row before reading and updating. A successful password grant only returns tokens after the v2 success function reports `recorded`; a concurrent lock returns the same generic 401 as other invalid credentials. Missing/invalid RPC results fail closed with 503. Failure recording also uses the v2 result. The password-verification hook now locks the same row and rejects a missing or currently locked account before resetting a successful attempt.

The Edge helper accepts only explicit `recorded` or `locked` JSON results. It treats a zero-row result, null, malformed result, thrown error, or RPC error as unavailable. A transactional SQL test exercises missing account, service-role permission, ten failures, lock enforcement, expiry, success reset, and second-account isolation without persisting fixture rows.
