# QST-429 Gemini Model Router Failover Integrity

## Status

Validated / local verified

## Problem

Quest Planningのprimary modelを環境変数で上書きすると、Provider Adapterの2回目の
試行でも同じ上書き値が優先され、fallback routeへ切り替わらなかった。QST-249の
「Primary失敗時にFallback modelへ切り替える」という契約を満たしていなかった。

## Changes

- primary用`GEMINI_MODEL_<ROLE>`とfallback用
  `GEMINI_FALLBACK_MODEL_<ROLE>`を分離した。
- 2回目の試行では失敗したprimary modelを候補から除外する。
- unknown、disabled、latest、experimentalを拒否し、Previewは明示flag配下に保った。
- Interactions Adapterは最初に解決したprimaryを保持し、再試行時だけfallback resolverを
  使用する。
- 同じProvider requestを再利用するため、trace IDとidempotency keyは試行間で変えない。
