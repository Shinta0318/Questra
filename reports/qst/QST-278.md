# QST-278 Quest Mission Task Trail Database Integrity Report

## Result

Completed on 2026-08-08 against hosted Supabase project
`dhbmgwarnrtelrcrmmfk`.

The Quest, Mission, Task and Trail hierarchy is now guarded in PostgreSQL, and
Mission completion is available only through an owner-scoped transactional RPC
after the Task completion contract has been satisfied.

## Changes

- Added Task parent, owner, dependency-parent and dependency-cycle validation.
- Added optional `trails.task_id` and validated Trail owner, Quest, Mission and
  Task context before writes.
- Preserved Trail history when a parent is deleted by atomically detaching its
  lower Mission and Task references.
- Added a direct Mission completion guard for both current and legacy hierarchy
  roles.
- Added `confirm_mission_outcome(uuid)`, which locks the Mission/Tasks, checks
  required Task completion and updates completion atomically.
- Updated Flutter Mission completion to call the RPC and reload the stored row.
- Changed newly created Flutter Missions to the formal `outcome` hierarchy role.
- Added Task context persistence to the Trail model and repository.
- Expanded the sanitized two-account acceptance runner and verifier.

## Rollback Boundary

The migrations are additive and separately versioned. A rollback must first
disable Mission completion writes, then drop the completion/validation triggers
and RPC, and only remove `trails.task_id` after confirming no retained Trail
depends on it. The pre-QST-278 schema head is `202608080001`.
