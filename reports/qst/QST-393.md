# QST-393 Clean Candidate Scope Partition

## Result

Implementation-ready. A clean candidate SHA has not been created yet.

## Changes

- Added a six-group implementation scope contract covering mobile runtime, mobile tests, Supabase runtime, release automation, product governance, and QST governance.
- Added a verifier that rejects unclassified and overlapping changed paths.
- Added a separate post-candidate phase that permits only the approved external evidence outputs.
- Connected the scope contract to the release workflow and clean-candidate orchestrator.

## Guardrails

- A dirty worktree is never described as a candidate.
- Product code cannot be changed while post-candidate evidence is being collected.
- Secret scanning remains a separate mandatory preflight.
- A clean SHA and evidence bound to that SHA are still required before External Beta.

## Validation

- `dart run tools/qst/verify_candidate_scope_partition.dart`
- `dart run tools/qst/verify_candidate_scope_partition.dart --require-clean` is expected to fail until the intended changes are committed and the worktree is clean.

## Remaining

- Review and commit the intended implementation scope.
- Generate the candidate manifest from the resulting clean SHA.
- Begin QST-394 hosted migration execution only from that SHA.
