# QST-432 Provider Payload Token Reservation Accuracy

## Status

Validated / local verified

## Problem

AI予算予約は`request.input`だけを4文字/tokenで見積もっていた。実際のInteractions
payloadにはsystem instruction、Structured Output schema、tool定義も含まれ、日本語は
英語と同じ文字比率ではないため、予約費用を過小評価する可能性があった。

## Changes

- providerへ送る上限と同じ40,000文字でinput JSONを切り詰める。
- input、system instruction、schema、toolsを一つのenvelopeとして見積もる。
- ASCIIは4文字/token、非ASCIIは1文字/tokenの保守的heuristicを使う。
- 15%の安全marginと32 tokenの固定overheadを加える。
- 実行後は従来どおりprovider usageと実行modelで精算する。
- candidate inventoryのFlutter test件数を現行値へ同期した。

## Validation

- Node 24 TypeScript実行: provider envelope estimate `126`、下限検証passed
- Backlog SSOT: passed、378 QST IDs
- Beta candidate manifest verifier: passed、draft / distribution-ready false
- Migration drift verifier: passed、latest local migration同期済み
- CJK、system instruction、schema、Google Search toolを含むDeno testを追加。
- Deno CLIはこの検証時点のPATHに存在せず、新規testのDeno実行はCIで継続確認する。
- 変更前のfallback model候補予約・attribution回帰4件はQST-431でpassed。

## Security and Privacy

見積りはメモリ内の長さ計算だけに使用し、payload本文をlogまたはDBへ追加保存しない。
秘密情報を入力へ加えず、provider API keyは引き続きserver側だけで扱う。

## Trade-off

専用tokenizerではなく安全側のheuristicであるため、特に日本語では実token数より多く
予約する場合がある。provider usageによる精算で差額は確定値へ置き換わる。
