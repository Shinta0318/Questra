# QST-340 Arc Memory Consent and User Control Center Report

## Status

ImplementedExternalEvidencePending

Arc Memoryの目的別同意、保存・参照gate、本人向けControl Center、provenance・retention、機微情報denyを実装した。実Supabaseへのmigration配備、二account RLS、撤回後cache、Web/Android実機操作は外部証跡待ちとする。

## Implemented

- `arc_personalization`同意がない場合、Memory extractionは新規Memoryを保存しない。
- Arc ChatとQuest Planningへ渡すMemoryは同意済みの場合だけ取得する。
- server-side Quest Planning Toolでも同意を確認し、同意なしでは空のMemory contextを返す。
- `覚えないで`、`記憶しないで`、`保存しないで`を含む会話をMemoryへ保存しない。
- 病気、診断、住所、passwordなどSensitive判定された内容をMemoryへ保存しない。
- Personal Memoryは90日、Standard Memoryは365日の保持期限を設定する。
- Memoryへ由来、source ID、抽出方式をprovenanceとして保存する。
- SettingsからArc Memory Control Centerを開き、ON/OFF、一覧、由来、保持期限を確認できる。
- 本人がMemoryを訂正、個別削除、一括削除できる。
- 同意OFFでも本人の確認・削除は維持し、Arcからの参照と新規保存だけを止める。
- 同意状態の変更履歴をappend-onlyの`arc_memory_consent_events`へ記録するmigrationを追加した。
- server insert triggerで現行同意とSensitive denyを検証する。
- AI参照用RPCはservice role限定、owner・consent・visibility・sensitivity・retentionを検証する。

## Rollback

Control CenterのUIは修正可能だが、同意なしの保存・AI参照、Sensitive Memory保存へ戻してはならない。Migration rollbackでも削除済みMemoryや撤回済み同意を復元しない。
