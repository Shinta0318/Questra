# QST-563 Honest Local Preview Credential Boundary

Status: Completed for local preview. Hosted authentication remains unverified.

- Date: 2026-10-16 (Asia/Tokyo)
- Branch/HEAD: `codex/initial-questra-structure-pr` / `a9d83bc`; dirty worktree, no immutable candidate or deployment.
- Source: a local code review found that `AuthController.login` created a profile from any ID/password when no local account had been registered. This could make an offline preview look like successful account authentication.

## Change

Offline credential login now requires a local account created in the same preview session. The entered login ID or email and password must match that account. Without one, the screen directs the developer to the explicit "モックを開く" action. Local failures have their own error context: the notice no longer claims the Hosted 10-attempt lockout applies or adds an email-confirmation/reset hint. The explicit mock-entry and auto-entry flows remain separate and unchanged. The Supabase-configured branch, Edge Function, database schema, and Hosted login policy were not edited.

## Boundary

This prevents false local authentication; it does not prove Supabase signup, email confirmation, password reset, account lockout, or live login. The offline login screen still contains links to email-confirmation and recovery screens even though offline mail is unavailable; removing or relabeling those links needs a separate UX decision and connected-mode test. The offline preview is still not a source of DB, Gemini, or RLS evidence. QST-563 is the seventh implementation item after QST-556; cross-functional review is due after QST-566.
