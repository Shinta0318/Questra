## Status

ImplementedE2EPolishPending

The hierarchy, persistence, Gemini contracts, transaction boundary, core UI, and cloud RLS proof are implemented. Formal completion remains gated by recorded Android/Web end-to-end runs and automatic progressive Task expansion after a Mission transition.

## Implemented

- Defined `Quest -> Active Route -> Mission -> Task` in Flutter and PostgreSQL.
- Added private `tasks`, Mission/Task dependency, migration preview, and Task event tables.
- Added owner-bound RLS and transactional plan approval. Preview approval creates one Route, outcome Missions, and current-Mission Tasks atomically.
- Added an explicit existing-data preview/apply flow. Uncertain classifications cannot be applied without review, and completed source items become completed Tasks.
- Derived Mission progress from required Tasks and Quest progress from completed required Missions. Mission completion additionally requires success-condition confirmation.
- Split Gemini planning into Route Mission generation/critic/targeted repair, followed by current Mission Task generation/critic/targeted repair.
- Updated Home to prioritize today's Task, Quest Detail to display outcome Missions, and added Mission Detail, Task Detail, and Quest Route screens.
- Removed the visible `Mission Plan` heading in favor of `Arcが描いた航路`.
