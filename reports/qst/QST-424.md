# QST-424 Arc Remote Provenance and Degraded Mode Boundary

## Status

ImplementedValidationPending

ローカル実装と自動テストは完了した。更新した `arc-chat` Edge Functionのhosted配備と、実Gemini応答によるtrace確認はQST-420およびQST-422で行う。

## Problem

SupabaseまたはGeminiの呼び出し失敗時に `LocalArcChatService` へ移行していたため、ローカル推論がQuest候補やMission変更案を返し、オンライン生成結果のように扱われる可能性があった。また、Settingsはオンライン応答の実成功をsession内で保持していなかった。

## Implementation

- Arc応答を `remoteVerified`、`localPreview`、`degraded` の3状態へ分離した。
- 生成元と有効なbounded traceの両方を確認できた応答だけを `remoteVerified` とする。
- remote失敗、Edge Function内fallback、無効traceはfail closedとし、Quest候補、Mission変更、Route変更、Quest CTAを破棄する。
- degraded状態では元入力を保持し、「もう一度試す」「入力を編集する」「あとで続ける」を表示する。
- degraded応答をArc Memoryへ記録しない。
- 成功時刻、sanitized source class、trace、latency classをアプリsession内だけに保持する。再起動後は未確認へ戻る。
- Settingsは実成功後だけ「応答確認済み」と表示し、失敗後は「再確認が必要」と表示する。
- Edge Functionへclient traceを渡し、検証後に応答へ返す契約を追加した。
- `ARC_REMOTE_PROVENANCE_V1` でprovenance表示状態を無効化できる。
