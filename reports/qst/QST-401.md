# QST-401 Incident Live Stop and Rollback Drill Execution

## Result

Local guard behavior verified in QST-402; hosted transaction semantics, artifact receipts and named-owner live execution remain pending.

## Changes

- Added an exact-Beta-project live drill runner bound to one clean candidate and rollback SHA.
- The runner records operator-attested distribution-stop references; it does not independently inspect the external receipt. Detection, stop and acknowledgement timestamps are mandatory, ordered, non-future and within one hour of detection.
- Quest Planning pause and restoration use atomic conditional REST updates matching the prior enabled flag, reason and timestamp. Restoration matches this run's unique stop marker, preserves the original reason, and refuses to overwrite concurrent operator changes.
- Current and rollback artifacts must live under the ignored artifact directory; their SHA-256 values are recorded and the current hash must match the candidate manifest.
- Rollback launch and stop communication require explicit external evidence references.
- Destructive database down migration is explicitly prohibited; forward remediation is the only recorded DB decision.

## Safety

- A failed feature-state restoration prevents completion.
- Service-role credentials are used in memory and are never written to evidence.
- No account identifiers, Arc content, Quest content, or reviewer free text are recorded.

## Current Blockers

- Feedback operations and the stop channel are not activated.
- A clean approved candidate and rollback artifact are unavailable.
- Supabase CLI and named operators are required for the live drill.
- The approved-candidate prerequisite still needs review against the final approval workflow so the drill does not become a circular prerequisite of approval.
