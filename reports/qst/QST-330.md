# QST-330 Progression and Premium Boundary Foundation

## Status

Implemented / hosted migration deployment pending

## Objective

StardustをQuestraの唯一のユーザー向け進捗値に統合し、Navigator Rankを累計Stardustから決定的に算出する。Premiumは進捗の強さではなくArcの伴走の深さとして準備し、決済は導入しない。

## Implemented

- Navigator Rankの混合スコアを廃止し、Stardustしきい値へ一本化した。
- ProfileのStardustとRankを統合し、現在値、進捗、次Rankまでの残量を表示した。
- Arc会話とMission作成のStardust付与を廃止した。
- Quest作成、Mission完了、Task完了、Trail記録のイベント種別を定義した。
- `award_stardust` RPCが所有者・完了状態・付与量を検証し、イベント台帳と残高を一度だけ更新する。
- クライアントは付与量を送らず、イベント種別と対象IDだけを送る。
- Free中核機能と将来の伴走深化候補をFeature Flag上で分離した。
- Entitlement、利用ポリシー、月次利用量、サーバー判定RPCの基盤を追加した。
- Betaの利用上限は未設定（unlimited）とし、Hard Paywallと決済を追加していない。

| 航路の開拓者 | 50 |

既存DBキーとの互換性を優先して4段階を維持した。段階名の追加は既存ユーザーデータ移行を含む別QSTで判断する。

## Stardust Rules

| Event | Amount | Validation |
| --- | ---: | --- |
| Quest作成 | 5 | Quest所有者 |
| Task完了 | 2 | Task所有者かつcompleted |
| Mission完了 | 10 | 親Quest所有者かつcompleted |
| Trail記録／Reflection | 3 | Trail所有者 |
| Quest完了 | 25 | Quest所有者かつcompleted（将来呼び出し用） |

Arc会話、Mission作成、画面表示回数では付与しない。同一`user_id + event_type + source_id`は再送しても再付与しない。

## Security and Integrity

- SECURITY DEFINER RPCは`auth.uid()`を必須とし、対象所有権を検証する。
- RLSはイベント・Entitlement・利用量を本人の読み取りに限定する。
- 付与量はサーバー固定で、Flutterから変更できない。
- Entitlementテーブルと利用ポリシーにクライアント書き込みPolicyを設けない。
