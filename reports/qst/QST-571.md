Status: Completed for entry preflight; real-account login remains unverified

- Date: 2026-10-17 (Asia/Tokyo)

- Trigger: The connected preview could report public Auth/Data API availability while its `auth-login` Edge Function was absent or rejected the browser Origin.

## Change

The connected preview launcher now posts an empty identifier and password to the hosted `auth-login` function before starting Flutter. It requires `401` with `invalid_credentials` and an exact `Access-Control-Allow-Origin` matching the selected local port. It uses only the existing publishable/anon key, does not disclose the key, and does not submit a real account identifier or password. Missing function, changed error contract, or wrong CORS blocks the launch.

This probe deliberately proves only the public login entry. It cannot prove that an existing password matches, that the login ID lookup works, that the database lock logic is deployed, or that an authenticated session persists. Those remain QST-569/QST-570 hosted acceptance work.
