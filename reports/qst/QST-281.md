# QST-281 Lower Specification Task Terminology Alignment Report

## Result

Completed on 2026-08-08.

Active product, release, privacy, UI and device-validation guidance now follows
the four-level `Quest -> Mission -> Task -> Trail` model. Mission is described
as an intermediate outcome and Task as the concrete executable action.
Historical QST text remains readable and is explicitly classified as evidence,
not current domain guidance.

## Changes

- Added `quest-mission-task-trail.md` as the canonical lower domain spec.
- Retained the old domain path as a compatibility and historical notice.
- Updated the Master Spec derived-document link and alignment tests.
- Added Task to Store copy, Beta readiness, Privacy, data request, authentication,
  Business, Guild and release guidance.
- Replaced visible `今日のMission` action wording with Task or priority-Mission
  wording according to responsibility.
- Updated Arc guidance to distinguish Mission outcomes from executable Tasks.
- Updated the real-device evidence key and verifier to the four-level journey.
- Classified the legacy product QST index so historical wording is not treated
  as active instruction.
- Added regression tests for active guidance, Privacy, device keys and historical
  compatibility.

## Validation

- QST-270, QST-281, Privacy and data-request tests: 10 passed
- Home and responsive regression tests: 21 passed
- Real-device validation contract verifier: passed
- Active Flutter source scan found no `今日のMission`,
  `Quest / Mission / Trail` or `Quest、Mission、Trail` remnants
