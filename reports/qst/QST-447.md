# QST-447 Hosted AI Budget Chain Deployment and Recovery Drill

## Status

Planned / external evidence pending. この文書は完了報告ではなく、Hosted実行前の証跡境界である。

## Why this remains open

- QST-445からQST-454の実装とローカル契約は揃っているが、同一candidate SHAで実Supabaseへ配備していない。
- QST-453のPostgreSQL property testと二operator並行claimをHosted環境で実行していない。
- Receipt binding、tool continuation attribution、schedulerのfeature flagは既定で無効であり、段階的canaryを行っていない。
- Provider応答喪失、receipt競合、自己承認拒否、誤補正回復の実運用時間を測定していない。

## Required execution order

1. Clean candidate SHA、migration head、Edge Function bundle checksumを固定する。
2. QST-453 property testと二operator concurrency drillを専用candidate dataで実行する。
3. Receipt bindingを有効化し、正常・replay・cross-reservationをcanary確認する。
4. Tool continuation attributionを有効化し、複数turnとfallbackのusage合計を確認する。
5. Schedulerを有効化し、重複schedule、lease回収、SLA通知、kill switchを確認する。
6. QST-454の全scenarioを実行し、acknowledge、containment、recovery時間を記録する。
7. 失敗時は証跡とopen caseを維持したまま直前のflag状態へ戻す。

## Evidence rules

- Service Role Key、利用者識別子、Quest、Mission、Trail、会話、provider本文を保存しない。
- 実行者、candidate SHA、schema version、flag遷移、集計結果、開始・終了時刻だけをcandidate-bound evidenceへ記録する。
- 一つでもCritical gateが失敗した場合はExternal Betaを`NO-GO`のまま維持する。

## Completion boundary

Hosted SQL、Edge Function、二operator、provider-backed canary、rollbackの実証が揃うまでQST-447をCompletedへ変更しない。
