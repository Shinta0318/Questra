# QST-347 Meaningful Progress Metrics and Experimentation

## Status

Implemented locally.

## Summary

Questra analytics now has a Beta metric tree centered on meaningful progress,
activation, trust, wellbeing guardrails, and AI cost bands. The implementation
extends the existing local-safe analytics boundary without storing Quest,
Mission, Trail, Arc Chat, prompt, memory, or personal contact text.

## Changed Files

- `apps/mobile/lib/core/analytics/analytics_event.dart`
- `apps/mobile/lib/core/analytics/analytics_service.dart`
- `apps/mobile/test/analytics_service_test.dart`
- `docs/analytics/beta_analytics_events.md`

## Acceptance Notes

- Added stable event names for:
  - activation step completion
  - meaningful progress
  - recovery action selection
  - trust feedback
  - wellbeing guardrails
  - AI cost observation
- Added allowlisted metadata keys for metric, activation, cohort, window,
  guardrail, cost, latency, accepted, and consent scope.
- Added service helpers for activation, meaningful progress, recovery, and
  guardrail events.
- Analytics failure remains non-blocking.
- Sanitizer still drops raw text fields such as prompt, chat, memory, content,
  message, email, and path.
- `docs/analytics/beta_analytics_events.md` now documents the QST-347 metric
  tree and guardrails.
