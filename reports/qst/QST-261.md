# QST-261 Task Creation and Generation Completion Path

## Status

ImplementedDeploymentE2EPending

Mission確定後の初回Task表示、既存MissionからのTask提案、手動追加、承認、保存、再読込までを実装した。新しい`expand_tasks`経路のSupabase Edge Function配備とAndroid/Web実機E2Eが未実施のため、正式完了にはしていない。

## Problem Resolved

- Gemini Planningは`currentTaskPlan`を返していたが、FlutterモデルがTask本文を保持していなかった。
- Supabase承認RPCは初回Taskを作成していたが、承認後にTask Controllerを再読込していなかった。
- ローカル確認ではMissionだけが保存され、Taskが作成されなかった。
- Task未作成のMission詳細には、Taskを生成または追加する操作がなかった。

## Implemented

- `ArcQuestGuide`へ構造化された初回Task候補を保持し、Geminiの`currentTaskPlan`を型付きデータへ変換した。
- Supabaseの計画承認後にMissionとTaskを再読込するようにした。
- ローカル経路でもMission確定と同時に、現在のMissionへ最初のTaskを保存するようにした。
- Mission詳細へ`Arcに提案してもらう`と`自分で追加`を追加した。
- AI提案は保存前ダイアログで内容と完了条件を確認し、明示承認後だけ保存する。
- Mission単位の`expand_tasks` APIを追加し、既存のStructured Output、Task Validator、Task Critic、低品質TaskだけのRepairを再利用した。
- 既存Taskを生成Contextへ含め、同じTaskの言い換えを再提案しないPrompt v2へ更新した。
- Task依存関係の参照先、自己参照、循環をサーバー側で拒否するようにした。
- Task生成中、失敗、再試行、重複候補の抑止を実装した。
- 手動追加フォームへ外部ラベル、必須チェック、文字数制限を追加した。
- 複数Taskを一括保存するRepository/Controller契約を追加し、依存関係を保ったまま再読込できるようにした。
