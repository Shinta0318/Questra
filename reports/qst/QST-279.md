Completed on 2026-08-08 against hosted Supabase project

Dynamic route review now understands the Task layer beneath each Mission.
Task changes remain proposals until approval, are applied in one database
transaction, and can restore the prior route without overwriting work completed
after the proposal was created.

## Changes

- Included Task status, dependencies, order and dates in route review input.
- Added Task-aware split, reorder, reschedule and add proposal handling.
- Excluded completed Tasks from new route focus and mutation targets.
- Added `target_task_id` and created-Task tracking to route change records.
- Added transactional apply and rollback RPCs for Task-aware proposals.
- Preserved the approval boundary: no Task changes before explicit acceptance.
- Added Flutter apply, reload and local undo support for Task route changes.
- Expanded the sanitized hosted acceptance runner and strict verifier.

## Rollback Boundary

The QST migration is additive. Before removing its RPCs or columns, disable new
Task-aware approvals and ensure no pending proposal references
`target_task_id`. Application rollback uses the stored Task snapshot, removes
only incomplete Tasks created by the accepted proposal, and preserves Tasks
completed after approval.
