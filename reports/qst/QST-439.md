# QST-439 Gemini Function Call Continuation Orchestrator

## Status

Validated / local verified

## Result

Gemini Interactionsの`requires_action`を、Questra Tool Server経由で処理し、
`store: false`を維持したまま最終Structured Outputまで継続する基盤を実装した。

## Implementation

- 初回`user_input`、providerのmodel step、`function_result`を次turnへ渡すstateless継続を追加。
- providerのthought signatureを含むstepを変更せず、メモリ内だけで保持する。
- 自動実行対象をallowlist済みread toolに限定する。
- unknown、preview write、approved writeを継続処理からfail closedで拒否する。
- Tool引数をRegistryのJSON Schemaで検証する。
- Quest ownership、Arc Memory consent、service-side RLS境界を既存Tool Serverで維持する。
- 最大3 turn、最大8 tool call、全体120秒、同一call循環検出を追加する。
- turnごとのidempotency keyを分離し、最終応答だけを既存schema/semantic validationへ渡す。
- 継続履歴をtoken予約へ含め、turn間のusageとGrounding metadataを集約する。
- continuation stepとtool resultはPlanning PassやDBへ保存しない。

## Product and Security Decisions

- Function Callingは参照情報の取得に限定し、MissionやQuestの変更を自動承認しない。
- `approve_plan_transaction`は従来どおり利用者が確認したpreviewのRPC承認経路だけで実行する。
- Tool失敗時は固定Missionへfallbackせず、`tool_failed`として安全に終了する。
- Arc Memoryは同意済みかつ最大5件だけを取得する。

会話履歴とfunction resultを後続requestへ明示的に渡す。provider-side保存へ依存しない。
