# QST-126 Beta Crash and Error Capture Plan

## Summary

内部Betaで発生するFlutter例外、Supabase保存失敗、認証・Media失敗、Arc Chat / Quest Guideのフォールバックを共通の証跡契約で扱う計画を定義した。外部collectorはQST-127のPrivacy Reviewまで無効とし、挑戦内容や会話本文を収集しない段階導入にした。

## Audit Findings

- App bootstrapにFlutter framework / unhandled async errorのglobal capture boundaryはまだない。
- Quest / Mission / Trailは失敗状態をUIへ返すが、build、operation、fingerprint、correlation IDを持つ証跡はない。
- Arc ChatとQuest Guideはlocal fallbackでUXを維持するが、fallback理由を構造化記録していない。
- 現状のfallbackと保存失敗UIはBetaに有効なため維持し、今後はprovider非依存のsinkから証跡を追加する。

## Plan Decisions

- 7種類のevent taxonomyと最小evidence schemaを定義した。
- Quest、Mission、Trail、Reflection、Arc Memory、Arc Chat本文、token、signed URL、raw request/exceptionを収集禁止にした。
- S0-S3、Beta停止、QST化をQST-125の判定へ接続した。
- 30日retentionとRelease Manager / assigned Engineering ownerのみのaccessを定義した。
- No-op `ErrorEvidenceSink`から承認済みproviderへ差し替える段階導入を推奨した。
- 外部provider有効化をQST-127 Privacy Reviewのgateにした。
