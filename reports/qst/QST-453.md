# QST-453 AI Budget SQL Property and Concurrency Tests

## Status

Implemented locally. Actual PostgreSQL property and two-session claim execution remain external evidence.

## Goal

AI予算のreservation、settlement、reconciliation、claim、correctionが、再送・競合・ランダム状態遷移でもcounter、owner、状態遷移、非負制約を壊さないことを検証可能にする。

## Implementation

- 永続counterとreservation集計をfull joinで照合するread-only propertyを追加した。
- idempotency key、provider receipt replay、case owner／trace、非負制約を検査する。
- TEMP table上でreserve／settle／release／expire／correctionを500回決定的に実行し、毎回集計不変条件を確認する。
- 異なるAuth reviewerの2つのpsql sessionを同時起動し、専用caseのwinnerが1人だけであることを検証するrunnerを追加した。
- runnerは隔離candidate、唯一のclaim候補、異なるreviewerをpreflightし、終了時にclaimを解放してauditを残す。
- stale correctionがcounter、reservation、request、audit更新より前に拒否されるtransaction順序を検証した。
- credential、Auth UUID、reservation、trace、provider interaction、journey本文を証拠へ記録しない手順を定義した。
