## 2026-10-31 Multi-pass evaluation runner correction

- The 200-case runner previously sent each `quest-planning-v2` request only once. The endpoint can return HTTP 202 `processing` while a multi-pass plan is still running, so the runner would mark an incomplete response as an evaluation failure and continue to the next case. That could misstate quality and consume provider quota without reaching a preview.
- The runner now continues the **same** Quest and idempotency key until `preview_ready`, with configurable per-case call and elapsed-time limits. An invalid continuation delay, exhausted budget, transport failure, or `retryable_error` stops the whole run; it does not silently turn a provider outage or 429 into 200 low-quality cases. Cleanup remains in the existing `finally` block, and no partial run results are written.
- Added no-network continuation tests and a release-gate invocation. PowerShell parsing, the continuation test, the consent preflight, and five Flutter source-contract tests passed. No Supabase account, Gemini call, hosted run, or pricing claim was made. The 200-case provider-backed and human-review gates remain pending; QST-256 is not complete.

## 2026-10-31 Version-policy gate correction

- The release gate previously required every case to have an identical set of actually invoked models, thinking levels, and Prompt keys. Multi-pass planning legitimately uses different paths by Quest, so a valid 200-case run could fail solely because one case needed grounding or a different thinking level.
- The gate now requires one Pipeline/Schema version pair, a consistent version for each Prompt key wherever that key is used, and resolved model-version and thinking evidence in every planning row. It still records the observed models and thinking levels, but does not mistake their legitimate case-level variation for a configuration change.
- A no-network test covers varied valid paths, Prompt-version drift, Schema drift, and missing/unresolved model evidence; the test is part of the release gate. This corrects a local false-negative gate only. It does not establish that the model router is pinned in Hosted, nor does it satisfy the pending provider-backed 200-case and human-review requirements.

## 2026-10-31 Cost and quota boundary correction

- The evaluation runner used eight disposable accounts and could undercount multi-pass token usage because checkpoint-replayed provider responses omit usage. It now uses one account and reads owner-scoped `ai_budget_reservations` for every planning pass of the current idempotency attempt. Missing, cross-owner, duplicate, unsettled, or malformed ledger rows abort the run. The estimated case cost uses the greater of recorded budget cost and the supplied per-token list-price estimate.
- Explicit synthetic-account legal/AI consent approval, provider-usage approval, and a positive estimated planning list-cost ceiling are now required before network access. The ceiling is checked between cases and after each completed case; it cannot prevent a single case from exceeding the ceiling. Safety moderation failure now stops the run instead of continuing through additional cases.
- No-network preflight, ledger, and Flutter source-contract tests passed. No provider calls or hosted writes were made. The ceiling is not a billing hard cap, does not include all Safety/grounding/failed-call charges, and cannot establish Free tier quota. A real 200-case run, human review, and hosted verification remain pending; QST-256 is not complete.

## 2026-10-31 Monthly admission-capacity preflight

- The current free-user Quest Planning policy permits 30 reservations per month, but a successful preview has at least ten provider Passes. The 200-case run therefore needs at least 2,000 admissions before optional repairs, far beyond one account's current policy. The runner now checks the hosted free policy **before creating its disposable account** and rejects missing, ambiguous, or insufficient capacity. This does not alter user quotas or use multiple accounts to evade them.
- The no-network quota tests cover the current 30/month policy, the premium-sized 150/month case, missing/duplicate policy rows, and the lower-bound threshold. This is a fail-closed local guard, not a solution for QST-256. A separately governed, cost-bounded evaluation allocation and provider quota evidence are still required; Free tier rate-limit type remains unknown.
