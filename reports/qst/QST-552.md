## Purpose and scope

The connected mock reached `auth-login`, but a real first login is not proven. A function returning tokens alone is insufficient: the same token must identify a Supabase Auth user and read that user's `user_profiles` row. The new probe checks those stages in sequence and reports only the failing stage/status. It does not retry, create accounts, change passwords, write Quest/profile rows, or output credentials, tokens, account IDs, or profile fields. Calling `auth-login` can itself update failed-attempt counters or last sign-in state; the probe is not side-effect-free.

The intended account was observed as confirmed and unlocked in QST-547. Its hosted password grant returned `invalid_credentials`; this is not evidence of an email-confirmation failure. A user-completed password reset and subsequent sign-in remain necessary. No real account credential was used for this QST.
