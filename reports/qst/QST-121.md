# QST-121 Report: Beta Account Setup Flow

## Summary

Prepared the beta account setup path so testers receive Japanese account copy,
can understand that the account exists to save their first Quest, and operators
have a concrete Supabase persistence verification runbook.

## Changes

- Localized beta login and account creation screens.
- Removed prefilled demo login credentials from the login screen.
- Replaced remaining account-related English UI labels in Profile and Trail
  media failure states.
- Added widget coverage for beta account setup copy.
- Added `docs/product/beta_account_setup_flow.md` as the operator/tester
  verification runbook.

## Acceptance

- Beta users can sign in or create an account from Japanese UI copy.
- The signup screen explicitly frames profile creation as preparation for
  saving the first Quest.
- The runbook defines how to confirm sign-in, first Quest creation, persistence
  after restart, and RLS ownership.
- Local fallback is documented as invalid beta persistence evidence.

## Validation

- `flutter analyze`
- `flutter test test/auth_beta_account_copy_test.dart test/widget_test.dart test/responsive_screen_smoke_test.dart --reporter compact`

## Remaining Evidence Before Wider Beta

A real Supabase project run is still required before beta approval:

- Supabase Auth sign-up/sign-in evidence.
- `user_profiles` row for the beta user.
- Quest row with matching `owner_id`.
- Restart/login persistence proof.
- Cross-account private Quest isolation proof.
