# QST-585 Fail-Closed Quest Safety Moderation Recovery

Status: In Progress (local verification only)

## Finding

The moderation endpoint returned `allow` when its AI provider returned no result or threw. The configured Flutter safety service also replaced non-consent remote failures with the local `allow` result. A request outside the deterministic keyword rules could therefore continue to Quest creation without the intended remote safety assessment.

## Change

- Return `503 safety_check_unavailable` when the moderation provider has no usable result. The deterministic local/server block and self-harm reframe remain available before the AI call.
- In a configured Flutter app, turn a remote safety failure into a retryable, non-accusatory blocked assessment. Retain the user's input; do not record it as an abuse signal.
- Reject an older server's `safety_fallback` allow response and an allow response with no recognized assessment source. Explicit legal-consent errors still propagate to their dedicated user messages.
- Arc Chat now preserves the dedicated consent message and failure reason when the preliminary safety request returns a legal error, rather than showing a generic remote failure.
- A retryable safety outage now retains the Arc chat input and exposes retry/edit actions; the retry uses that same input rather than a stale or empty value.
