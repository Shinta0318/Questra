# QST-435 Gemini Empty Output Fail-Closed Handling

## Status

Validated / local verified

## Problem

GeminiがHTTP 200を返しても`output_text`とmodel outputが空の場合、空文字を成功応答として
精算し、Arcが無言のまま画面へ返る可能性があった。

## Changes

- text抽出直後に空応答を検査する。
- primaryの空応答はfallback modelへ一度だけ切り替える。
- fallbackも空なら`malformed_output`として予約を解放する。
- 失敗へ実行modelとthinking levelを保持する。
- Structured OutputのJSON解析より前に検査し、空結果を保存経路へ渡さない。
- Provider契約のtype-only importを明示し、runtime-neutralなmock検証を可能にした。

## Validation

- Node mockで2 modelの空HTTP成功、予約解放、malformed outputを確認する。
- Flutter contract testへ判定順序と失敗文言の検査を追加した。
- Backlog SSOT、candidate manifest、diff checkを実行する。

## Security and Privacy

raw provider responseや秘密情報をlogへ追加していない。利用者向けUIは既存のArcらしい
再試行案内を利用し、provider内部文言を直接表示しない。
