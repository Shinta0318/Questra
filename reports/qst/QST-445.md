# QST-445 Auth-bound Reconciliation Operator Identity

## Status

Completed locally. Hosted migration execution and the two-operator drill remain external evidence.

## Goal

AI予算reconciliationの人間操作をSupabase Auth主体へ一意に結合し、任意operator IDのなりすまし、同一人物による自己承認、自動workerによる人間判断操作をDB境界で拒否する。

## Implementation

- Enabled human operatorへ一意な`auth_user_id`と`identity_bound_at`を必須化した。
- Migration前のAuth未結合human operatorは、監査履歴を消さず自動無効化する。
- 人間向けRPCからoperator ID引数を排除し、`auth.uid()`でoperatorを解決する。
- 一般authenticated userはwrapperを呼べても、registry照合後かつデータ取得前に拒否される。
- Service Roleは`service_worker`としてqueueのclaim/releaseだけを実行できる。
- 補正の申請、承認、適用、case解決をAuth結合済みhuman operatorへ限定した。
- RequesterとApproverが同じAuth userである補正をtriggerで拒否する。
- 承認したApproverだけが補正を適用できる。
- Operator eventへ`human`、`service_worker`、`legacy_unbound`を自動記録する。
- Auth user削除前の無効化、証跡保持、forward-safe rollback、hosted二operator drillを文書化した。

## Evidence boundary

ローカルテストはSQL文字列契約と既存Flutter回帰を確認するが、PostgreSQL上の実行、JWTを分けた一般利用者・reviewer・approverの拒否／許可、同時claim、Auth user削除時の挙動を代替しない。ローカルSupabase CLIがPATH上にないため、この作業単位ではDB lintやlocal migration replayを実行していない。

実SupabaseへMigrationを配備し、`supabase/tests/qst_445_auth_bound_reconciliation_operator.sql`と二operator drillをcandidate SHAへ結合するまで、External Beta配布は`NO-GO`を維持する。
