# QST-369 Candidate Asset Package Hygiene and Ownership Workflow

## Result

Implementation completed. Candidate package hygiene passes; public release
remains blocked because Arc asset chain-of-title evidence and Product/Legal
approval are pending.

## Implemented

- Generated a candidate-SHA package manifest for the exact Flutter asset bundle.
- Confirmed seven runtime Arc expressions are included and six mock/reference
  images are excluded from Flutter Web/Android packages.
- Added byte-size and SHA-256 checks so a changed image invalidates the manifest.
- Added a release-only gate requiring both provenance approval and candidate
  package approval.
- Added an ownership workflow covering original source, generation or commission
  evidence, applicable terms, third-party restrictions, intended use, and dated
  Product/Legal review.
- Added the package status to the Beta candidate and External Beta Go/No-Go
  evaluators.

## Validation

- `dart run tools/qst/generate_candidate_asset_package.dart`: generated 7
  runtime assets and 6 excluded repository references.
- `dart run tools/qst/verify_candidate_asset_package.dart`: passed package
  hygiene.
- `dart analyze` for package tools: passed.
- Focused Flutter test: see final QST validation result.
- `--require-release`: intentionally blocked until chain of title is approved.

## Guardrails

- A reference mock cannot enter the candidate bundle.
- Repository presence does not prove ownership.
- A hash change does not preserve prior approval.
- Product/Legal approval is never generated by tooling.
- Credentials, signatures, and private evidence are not stored in the manifest.
