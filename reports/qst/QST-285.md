# QST-285 Task-Linked Trail Capture

## Result

Completed on 2026-08-08. A user can now leave a Trail directly from Task Detail
while retaining the full Quest -> Mission -> Task hierarchy through creation,
local state, Supabase persistence, reload, cards, and Timeline presentation.

## Implementation

- Added a Task Detail action for completed and in-progress Task Trails.
- Added an encoded Task Trail route that carries hierarchy IDs and display names.
- Opens the Trail composer once when entering from a Task.
- Shows Quest, Mission, and Task breadcrumbs before the user saves.
- Persists `quest_id`, `mission_id`, and `task_id` through the existing repository.
- Replaced raw internal IDs in Trail cards with readable hierarchy labels.
- Added the same hierarchy labels to each linked Timeline entry.
- Added structural validation so a Task cannot be linked without its Mission.
- Reuses one stable Trail ID across composer retries and replaces optimistic state
  with the same ID, preventing duplicate Trails when a response is uncertain.

## Persistence Evidence

- `SupabaseTrailRepository` writes and reads `task_id`.
- Hosted two-account acceptance confirms Task-linked Trail reload.
- Hosted database trigger rejects cross-parent Trail writes.
- Repository upsert and stable client ID make retries idempotent.
- No database migration was required for this QST; the current hosted head remains
  `202608080005_task_aware_route_replanning.sql`.
