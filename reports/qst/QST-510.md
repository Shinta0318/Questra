# QST-510 Task Mutation Owner Switch Race Guard

## Summary

Task保存または並び替えの通信中にアカウントが切り替わると、旧ownerの遅延応答が
新ownerの画面状態へ混入し得た。Task Controllerにowner世代とowner IDの双方を
確認する境界を追加した。

## Changes

- 認証主体変更時にTask owner世代を更新する。
- durable queue書込後、repository応答後、queue消去後にowner境界を確認する。
- staleな保存成功・失敗ではTask state、Mission進捗、同期表示を更新しない。
- staleな並び替え成功・失敗では新ownerへ旧並び順を反映しない。
- 旧ownerの未確定操作はowner別durable queueに残し、再ログイン後の確認対象とする。

## Master Spec Alignment

個人の挑戦データを別アカウントの画面へ混入させない。操作失敗時の入力保持と
再試行可能性は維持し、旧ownerの結果で新ownerの進捗を変更しない。

## Residual Risk

- 実Supabaseの二アカウント同時操作と物理端末での認証切替は未実証。
- 複数Taskの並行保存と同一owner durable queueの競合は別途検証が必要。
- Route snapshot復元などTask Controllerの他の長時間処理は本QSTの対象外。
