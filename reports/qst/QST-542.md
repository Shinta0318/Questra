# QST-542 Signup Confirmation Callback Session Separation

Status: In Progress / local_partial

## Problem

QST-539 sent signup confirmation to the same login or native callback used by ordinary auth flows. Supabase Flutter could exchange the returned PKCE code into a session, contradicting Questra's requirement for a first explicit login. The pinned 2.14.2 SDK also predated Web callback URL cleanup and hash-route preservation fixes.

## Local implementation

- Upgrade `supabase_flutter` to the current compatible stable 2.x release and use its callback predicate. Signup confirmation returns to dedicated Web and native URLs and is excluded from session exchange; password recovery remains eligible.
- Remove one-time confirmation parameters from the Web URL before SDK initialization. Route the native confirmation deep link to a public return screen, including cold start. The screen does not claim receipt or verification; it offers explicit login and resend help.
- Preserve recognition of older Web `/#/login` confirmation links carrying auth parameters. Ordinary login and Quest URLs are not treated as callbacks.
- Update the local Supabase redirect list, external Beta redirect gate, and auth specification. Hosted Beta settings and accounts were not changed.

This verifies local Web routing and cleanup, not a real Supabase email round trip or actual session exchange.
