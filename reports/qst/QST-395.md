# QST-395 Hosted Dynamic RLS Inventory and Two-Account Replay

## Result

Implementation-ready; hosted execution remains pending.

## Changes

- Added a transactional hosted inventory test for every physical or partitioned table in `public`.
- The test rejects any table without RLS and any policy-free table that still grants client DML privileges.
- Cloud evidence capture now compares the complete hosted table-name set with the set derived from local migrations.
- The inventory count, inventory digest, SQL checksum, and rollback state are recorded before the existing two-account replay.

## Current Evidence

- Local migrations define 98 public tables and pass the static dynamic coverage gate.
- The latest migration and hosted inventory test have not yet been executed on the linked project from a clean candidate SHA.
- Historical two-account evidence remains stale and is not reused as current candidate evidence.

## Validation

- `dart run tools/qst/verify_dynamic_rls_coverage.dart`
- `dart run tools/qst/verify_cloud_rls_evidence.dart`
- Cloud completion additionally requires `--require-cloud` after QST-394 deployment.

## Safety

- Both inventory and behavior suites run inside transactions and roll back.
- Evidence excludes credentials, account identifiers, and private journey content.
- Missing or unexpected hosted tables fail the set comparison.
