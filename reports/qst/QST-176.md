# QST-176 Quest Planning Input and Mission Relationship Repair

## Status

Completed locally.

## Goal

Arcへの相談からQuestを作る入力体験を修復し、QuestとMissionの役割、親子関係、進捗操作を画面と永続化の両方で明確にする。想定外の願いについても、生の相談文を横流しせず、本人が採用・編集した結果だけを次回計画へ活用できる基盤を作る。

## Implementation

- 「相談から航路を描く」に外部ラベル、複数行日本語入力、任意の期限選択を追加した。
- 元の相談内容をQuestの説明として保持し、Geminiへ期限を含めて送るようにした。
- 全機能画面の `labelText` を廃止し、共通 `QuestraFieldLabel` へ移行した。
- 初回アカウント登録、ログイン、パスワード再設定の入力欄も同じ方式へ統一した。
- Quest詳細に「このQuestのMission」と親Quest名を表示した。
- Missionに0 / 25 / 50 / 75 / 100%の進捗更新を追加し、Quest全体進捗へ部分進捗を反映した。
- Mission完了後も手動追加とArc再提案を常時利用できるようにした。
- Mission一覧から親Quest詳細へ移動できるようにした。
- Bottom NavigationとNavigation RailのArcから金色の円形装飾を除き、他タブと同じ選択表現へ揃えた。
- 採用数、編集数、期限帯、カテゴリだけを所有者単位で保存する `quest_planning_feedback` を追加した。生の相談文は保存しない。
- 過去の集計結果を次回の `arc-quest-guide` へ渡し、未知の願いでは発見優先の航路を生成する指示を追加した。

- Raw consultation text, chat text, and generated Mission text are not copied into the feedback table.
- Feedback is owner-bound through RLS and is used only for that owner's future planning context.
