# QST-434 AI Budget Idempotent Reservation Recovery

## Status

Implemented / external deployment pending

## Problem

DBで予約が完了した直後にHTTP応答だけ失われると、同じidempotency keyの再試行は既存予約を
回収できず、providerを呼べないまま予約が期限まで残る可能性があった。

## Changes

- v2予約RPCを同じadvisory transaction lock内で再入可能にした。
- 有効な`reserved`行、同じprovider、十分な予約費用を満たす場合だけ同じIDを返す。
- settled、released、expired、費用不足は明示理由付きで拒否する。
- budget RPCを最大2回、各回timeout付きで再試行する。
- 429と5xx、network error、timeoutだけを再試行し、通常の4xxは再試行しない。
- settleとreleaseは既存RPCの冪等分岐を利用する。

## Validation

- Node mockで初回応答喪失、2回目の予約回収、provider未呼び出しを検証する。
- Flutter contract testへlock、費用、status、retry境界の検査を追加した。
- Migration drift、hosted deployment plan、Backlog SSOTを再検証する。

## Security and Privacy

回収はservice roleに限定し、user、operation、idempotency keyを一致させる。raw prompt、API key、
個人データを新しいlogや証跡へ保存しない。

## Evidence Boundary

Migrationは実Supabaseへ未配備であり、同時実行とHTTP応答喪失のhosted検証は未完了。
External BetaはNO-GOを維持する。
