# QST-368 Data Rights Fulfillment and Retention Drill

## Result

Local implementation and contract drill completed. Hosted owner-isolation,
worker execution, provider retention, and backup restoration evidence remain
pending, so External Beta remains blocked.

## Implemented

- Added server-assigned operational SLAs: 24 hours for consent withdrawal, 72
  hours before account deletion processing, and 30 days for correction review.
- Added a transactional service-role consent-withdrawal worker that revokes the
  relevant consent and removes derived business signals.
- Added a service-role correction claim and resolution flow with allowlisted
  resolution codes. The operator must apply the domain correction before marking
  it `applied`; the worker does not invent or rewrite user data.
- Added content-free fulfillment receipts and aggregate-only metrics.
- Classified deletion provider errors before persistence and removed request IDs
  from worker responses.
- Added a provider/backup retention register that fails closed while facts and
  human approvals remain unknown.
- Added local and hosted drill contracts plus an operational runbook.

## Privacy and Security

- App users cannot call operator or worker RPCs.
- Receipt rows contain no owner ID, email, phone, request text, Quest, or Trail
  content.
- Evidence records no account identifiers, request content, credentials, or
  worker secret.
- SLA deadlines and policy versions are assigned by the server even when a
  client attempts a direct insert.
- Unknown provider retention is not treated as approval.
- Database rollback remains forward-only and non-destructive.
