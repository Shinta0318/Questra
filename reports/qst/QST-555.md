## Finding and change

`verify_supabase_beta_bootstrap.dart` expected a `/v1beta/interactions` endpoint, model name, provider key, `store: false`, and generation settings directly in `_shared/ai_provider.ts`. `verify_beta_privacy_copy_readiness.dart` also expected `store: false` there. The current provider delegates to `quest_planning/interactions_adapter.ts`, with model policy in `model_registry.ts` and budget admission in `ai_budget_admission.ts`. Both checks failed even though the relevant implementation remained present. Google's official Interactions API reference currently documents the stable `/v1/interactions` endpoint: https://ai.google.dev/api/interactions-api-v1 (checked 2026-10-08).

The verifiers now follow that delegation and check the adapter's server-side key, `store: false`, generation config, bounded timeout, model/preview policy, and AI budget reserve/settle/release. The privacy verifier specifically follows the direct generation entry to the stateless adapter. A shared source-contract helper prevents the two gates from drifting apart.

## Verification and limits

- Before change, Supabase bootstrap failed on nine outdated provider snippets; privacy readiness failed on missing `store: false` in the entry file.
- `dart run tools/qst/ai_provider_contract_test.dart`: PASS. Removing `store: false`, entry delegation, budget reservation, or preview guard from in-memory fixtures makes the contract fail.
- `dart run tools/qst/verify_supabase_beta_bootstrap.dart`: PASS for static contract. `dart run tools/qst/verify_beta_privacy_copy_readiness.dart`: PASS for static contract.
- These are source-presence checks, not Deno typechecking, real Gemini calls, a proof of price/quality, or Hosted deployment evidence. QST-547 QR-15/17 and external Beta NO-GO remain open.
