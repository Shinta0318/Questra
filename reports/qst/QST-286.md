# QST-286 Route Proposal Stale Conflict Protection

## Result

Completed on 2026-08-08. A route proposal can no longer overwrite Mission or
Task progress that changed after the proposal was created. Freshness is checked
in Flutter for immediate feedback and again inside the hosted approval boundary.

## Implementation

- Added deterministic Quest, Mission, and Task route snapshots.
- Added client conflict detection that ignores collection ordering but detects
  status, progress, dependency, schedule, deadline, and route changes.
- Added `stale` as an explicit proposal lifecycle state.
- Added stale reason and conflict snapshot to domain and repository contracts.
- Added a refresh action that creates a new proposal from current progress while
  retaining the old stale proposal as audit history.
- Added clear UI messaging when approval loses a freshness race.
- Added authoritative server-side base snapshots at proposal insert time.
- Wrapped all three route approval RPCs with the same stale guard.
- Locks Quest, Mission, and Task rows before comparing and applying changes.
- Returns a structured stale result rather than throwing and rolling back the
  audit status.
