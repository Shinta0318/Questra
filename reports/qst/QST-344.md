# QST-344 Report: First Ten Minutes Activation Journey

## Status

Implemented local product contract and Home activation surface. Moderated cohort evidence, hosted persistence evidence, and production analytics funnel are still pending.

## Objective

Help a first-time user understand the promise, complete trust/onboarding gates, express one wish, confirm the first Quest, and start the first Task without a long terminology tour.

## Changes

- Added `ActivationJourneyService` to resolve the user's first-ten-minute stage from profile, Quest, Task, and Task load state.
- Added a Home activation card that appears only until the first Task has started or completed.
- Kept first-use language focused on Arc, Quest, and Task instead of introducing the full glossary.
- Routed activation actions to legal/signup, onboarding, Arc wish input, Quest confirmation, or the first Task focus path.
- Added tests for trust gating, wish input, Quest confirmation, first Task, and completion.

## 2026-10-31 Active Quest and actionable Task follow-up

- The activation resolver previously treated a completed or started Task from an archived Quest as completion of the current journey. It could also offer a deferred, blocked, dependency-blocked, or archived-Quest Task as the first action because `isOpen` is broader than `canStart`.
- It now considers only Tasks belonging to active Quests and uses the existing Task availability rule to select a startable first Task. When none is startable, it returns to Quest confirmation instead of promising that a blocked Task can start. This changes no Quest, Mission, or Task persistence state.
- Nine activation unit tests and four Home widget tests passed, including archived completed/ready Tasks, deferred/blocked/dependent Tasks, and the no-startable-Task state. Targeted Dart analysis reported no issues. Connected Web/Android behavior, cross-Mission dependency UX, and production activation analytics remain unverified; QST-344 stays in progress.
