# QST-294 Quest Creation Form UX Redesign

Status: ImplementedAndroidEvidencePending

## Summary

Quest作成・編集とArcの航路作成フォームを、長文を考えながら入力できる1カラム構成へ刷新した。ユーザーが決める内容と、Arcが保存・航路生成後に分析するTheme・難易度・予想期間を分離した。

## Changes

- Design Systemへ `AppFieldSizes` を追加し、short / medium / long input、action、field gap、Quest form max widthを定義。
- Quest名を1〜2行、叶えたい理由と成功条件を3〜6行の動的textareaへ変更。
- 長文項目の横並びを廃止し、PC・Tablet・Mobileで1カラムへ統一。
- Questフォームを最大780pxで中央配置。
- 希望達成時期を `YYYY / MM` のユーザー所有値として表示。
- Theme手入力とDifficulty表示欄を初期入力から外し、Arcの読取専用分析カードへ統合。
- 成功条件を `QuestUnderstanding.successEvidence`、理由を `motivation` として既存Quest保存契約へ接続。
- Arc航路作成フォームも同じ長文・1カラム・読取専用分析ルールへ統一。
- Arc Guide確定時にQuest DNA、Quest Understanding、Plan QualityをQuestへ引き継ぐよう補強。
- 日本語IME、モバイル、デスクトップ最大幅をWidgetテストで固定。

## Specification Notes

- Themeは既存保存契約との互換性のため内部値を維持するが、新規フォームでは必須入力にしない。AI結果がない場合のみ既存fallback値を利用する。
- DifficultyもDB互換用のenumを維持するが、ユーザー入力には戻さない。Quest Evaluationを正式表示値とする。
- Arc支援は既存の「Arcと話しながら決める」導線を維持した。フィールド内での提案適用は、Planning Pipelineの承認済み出力へ接続する次段階とする。
