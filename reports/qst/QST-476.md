# QST-476 Trail Cross-functional Integrity Review II

## Scope

QST-466〜475を対象に、コード、UI/UX、AI境界、DB、セキュリティ、Master Spec準拠を横断レビューした。

## Findings and fixes

### 1. Remote pagination offset drift

ローカルでTrailを追加するとController state件数が増え、次ページのremote offsetまで進んで一件飛ばす可能性があった。

- remoteから実際に消費した件数を`_remoteOffset`として分離した。
- refresh generationを追加し、古い追加読込responseを新しい一覧へ混在させない。

### 2. Cross-owner delete recovery

削除待機中に利用者が切り替わり、その後削除が失敗すると、前利用者のTrailを現在stateへ復元する可能性があった。

- response時に現在ownerを再確認する。
- owner変更後は旧Trailを復元せず、旧owner向け通知も表示しない。

### 3. Stale media overwrite

画像batch取得中に新しい画像を追加・削除しても、古いresponseが新しいattachment stateを上書きする可能性があった。

- `setAttachment`と`clearAttachment`でgenerationを更新する。
- 変更後に戻った古いbatch responseを破棄する。

## Review results

- Code: owner、generation、remote offsetの責務をController内で分離した。
- UI/UX: 未読込ページがあるfilter空状態はTrail不在を断定せず、追加読込へ案内する。
- AI: AI生成やArc人格には変更なし。Trail Memory enrichmentは既存のbest-effort境界を維持する。
- DB: queryはowner_id境界、明示列、limit/rangeを維持する。schema変更なし。
- Security: 利用者切替後の旧ownerデータ復元を防止した。RLS静的gateは40 table／51 policyで合格した。
- Master Spec: Quest → Mission → Task → Trailの階層と、Trailを旅の記録として扱う原則を維持する。
