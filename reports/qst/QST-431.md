# QST-431 Fallback AI Budget Reservation Integrity

## Status

Implemented / external deployment pending

## Problem

QST-429でprimaryとfallbackを異なるmodelへ確実に切り替えられるようになった一方、
AI予算はprimary modelだけで予約していた。fallbackの単価がprimaryより高い構成では、
月次上限に対する予約額が実際の最大費用を下回る可能性があった。

## Changes

- `reserve_ai_usage_budget_v2` RPCを追加した。
- Adapterはprimaryとfallbackの候補modelを重複除去して一括予約する。
- RPCは有効な価格を全候補へ要求し、欠落時はprovider呼び出し前にfail closedする。
- 候補中で最も高い推定費用を既存の原子的予約RPCへ委譲する。
- 精算は従来どおり、実際に実行したmodelと実token数で行う。
- RPCの実行権限は`service_role`だけに限定した。

## Validation

- Flutter contract tests: 7 passed
- Deno model/router/adapter tests: 4 passed
- Deno check: passed
- Fallback mock reservation candidates:
  `gemini-3.6-flash`, `gemini-3.5-flash`
- Model attribution regression:
  primaryからfallbackへの試行順と最終modelを維持

## Security and Privacy

- Clientから予約RPCを呼び出せない。
- 未登録modelの費用をゼロ扱いしない。
- API key、service-role値、prompt本文、ユーザー識別子を新しいlogへ追加していない。
- 予約の冪等性と月次上限判定は既存のtransaction内RPCを再利用する。
