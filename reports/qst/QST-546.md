# QST-546 Gemini Search Query Attribution Contract

Status: In Progress / local_partial

## Finding

Google's Interactions API documents `google_search_call.arguments.queries`, but the local extractor only read `query`/`queries` directly on the step. A real nested call could be counted as zero billable searches. The regression test reproduced `0 !== 1` before the fix.

## Local implementation

- The extractor now reads the nested `arguments.queries` shape as well as the older direct fields. Unique non-empty query text remains the billable count, consistent with Google's [Grounding billing description](https://ai.google.dev/gemini-api/docs/google-search), checked 2026-10-07.
- If a search-call step has no recognized query field, the metadata is marked incomplete and `verifiedGroundingQueryCount` rejects zero-query settlement. The user does not receive such a response as grounded guidance. No query text is written to the budget ledger by this change.
- No hosted AI function, migration, or production data was changed.

## Verification

- The nested-query fixture failed with zero billable queries before the patch and passed with one afterward.
- A query-less search-call fixture must not settle as zero or return a grounded answer. Existing direct-query behavior remains supported.
- Tests are mocked; the deployed model response and reconciliation of any already-uncertain reservation are not verified.
