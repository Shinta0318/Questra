## Finding and implementation

The public `auth-login` handler checked Content-Length but then called `req.text()`, which buffers the whole body before checking the real UTF-8 length. A client could omit or falsify Content-Length and send an oversized body. `JSON.parse('null')` could also leave a null payload that the handler dereferenced.

The handler now reads the body incrementally and stops once it exceeds 4KB or the total 10-second read deadline. The declared length is an early rejection only; the actual byte count is authoritative. Invalid JSON, non-object JSON, and invalid UTF-8 are rejected before account lookup or password grant. Existing response status contracts remain 413 for oversized input and 400 for malformed input; an incomplete request that exceeds the read deadline receives 408.
