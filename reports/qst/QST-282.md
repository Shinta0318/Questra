## Findings

### Critical

1. The same candidate has not completed Android and Web journey, IME,
   accessibility and retry evidence. Carried into QST-283.
2. Candidate manifest and readiness files still contain older test totals and
   blocker descriptions. They cannot authorize distribution. Tracked by QST-290.

### High

1. Arc Chat context includes Quest, Mission, Trail and Memory but not focused or
   recent Tasks. Tracked by QST-284.
2. Trail persistence supports `task_id`, but the active Task-to-Trail UI does not
   carry and display that context end to end. Tracked by QST-285.
3. Route proposals need stale-snapshot conflict protection when progress changes
   after proposal creation. Tracked by QST-286.
4. Task retry state is active-session only and is lost on process termination.
   Tracked by QST-287.

### Medium

1. Task due dates and dependencies are not yet used consistently by Signal and
   Arc reminder surfaces. Tracked by QST-288.
2. Arc Memory does not yet model Task lifecycle links as a first-class source.
   Tracked by QST-289.
3. Privacy copy includes Task, while export and deletion remain preparation-only
   UI. Tracked by QST-291.
4. Long routes need explicit query and frame budgets. Tracked by QST-292.

## Review Fix Applied

The route review dialog previously used a generic raw-map diff and stated only
that Mission or deadline values remain unchanged before approval. It now labels
Quest, Mission or Task targets, translates operation and field names, summarizes
list changes, and explicitly includes Task in the approval boundary.
