# QST-473 Trail Media Batch Loading

## Goal

Trail一覧と追加ページの画像metadataを1件ずつ取得せず、owner境界内の一括取得で通信量と表示遅延を抑える。

## Implementation

- Media RepositoryへTrail ID配列の一括画像取得契約を追加した。
- Supabaseはowner_id、related_table、related_id配列、media_typeを一つのqueryで制限する。
- 各Trailでは最新画像一件だけをmapへ採用する。
- Controllerは既に取得済みのattachmentを保持し、追加ページの未取得IDだけを問い合わせる。
- 利用者が切り替わった瞬間に前利用者のattachment stateを破棄する。
- 古い非同期responseをgenerationとowner再確認で無視する。

## Evidence

- `apps/mobile/lib/features/media/media_repository.dart`
- `apps/mobile/lib/features/trail/trail_controller.dart`
- `apps/mobile/test/qst_473_trail_media_batch_loading_test.dart`

## External boundary

一括取得、最新一件、owner分離はInMemoryで検証する。hosted Supabaseのquery latencyとStorage signed URL描画は外部性能証跡が必要。
