# QST-582 Candidate-Bound Edge Function Deployment Evidence

Status: In Progress (local evidence contract only)

## Finding

The Hosted-required Supabase bootstrap verifier checked whether each Edge Function was labeled `deployed` and had a date, but did not bind that entry to the candidate commit. Old deployment entries could therefore be presented next to a newer migration head. QST-578 QR-37/43 requires one immutable candidate for Hosted parity, and QST-581 adds new consent gates that must not be mistaken for the older deployed function versions.

## Change

- Record each function's deployment time **after** its successful CLI deployment instead of assigning one pre-deployment time to all functions.
- Record the clean candidate source commit on every function entry in the sanitized Beta project manifest.
- Make `--require-cloud` reject missing, duplicate, malformed-date, or different-commit function entries and require a clean-at-deploy claim. Keep the static preflight separate from Hosted proof.
- Add standalone negative/positive tests for the function evidence contract.

## Local Verification

- PowerShell parser on `bootstrap_supabase_beta.ps1`: passed; no deployment executed.
- `dart run tools/qst/verify_supabase_beta_bootstrap_test.dart`: passed for valid, missing, duplicate, mismatched-SHA, and invalid timestamp entries.
- `dart run tools/qst/verify_supabase_beta_bootstrap.dart`: static preflight passed.
- `dart run tools/qst/verify_supabase_beta_bootstrap.dart --require-cloud`: failed as intended on the current manifest, including old function entries without a candidate SHA and the missing latest Hosted migration.
- `dart run tools/qst/verify_backlog_ssot.dart`: passed with 528 QST IDs. Candidate-bound Hosted execution remains unverified.

## Boundary

The SHA in a local manifest is operator-recorded evidence, not a cryptographic attestation by Supabase. This change prevents an internally inconsistent manifest from passing; it does **not** prove that the remote function source matches the SHA. A clean candidate, ordered migration replay and Hosted deployment, function-version inspection, smoke tests, two-account RLS, and rollback evidence remain required. External Beta is **NO-GO**.
