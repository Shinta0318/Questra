# QST-370 Privacy-Safe Observability Sink Integration

## Result

Local implementation completed. Hosted collection remains disabled until a
clean candidate passes owner-isolation, retention, alert delivery, and rollback
drills.

## Implemented

- Added an authenticated Supabase RPC that derives `owner_id` from `auth.uid()`
  and accepts only the fixed `RuntimeEvidence` field allowlist.
- Added server-side token, classification, timestamp, required-field, and
  unknown-field validation.
- Denied direct client writes and provided owner-only metadata read access.
- Added 30-day retention and a bounded service-role purge worker.
- Added a metadata-only S0/S1 alert queue, allowlisted resolution codes, and
  aggregate-only SLO windows.
- Added a Flutter hosted sink that is disabled by default and swallows transport
  errors so evidence collection cannot break the product journey.
- Connected Arc remote fallback to the sink using normalized timeout or remote
  failure codes; no exception message or chat content is transmitted.

## Validation

- `dart run tools/qst/run_privacy_safe_observability_drill.dart`: passed.
- `dart run tools/qst/verify_privacy_safe_observability.dart`: passed.
- QST-358, QST-365, QST-370, and Arc Chat focused tests: 23 passed.
- `flutter analyze --no-pub`: passed.
- Hosted evidence: pending by design.

## Guardrails

- Hosted collection requires `ENABLE_RUNTIME_EVIDENCE_SINK=true`; default is
  false.
- Raw exception text, account identifiers, contact data, credentials, journey
  content, Arc conversation, media, and URLs are not schema fields.
- Alert payloads omit event owners.
- Event replay is idempotent per owner/event ID.
- Local tests do not prove hosted alert delivery or rollback.
- No destructive database rollback is added.
