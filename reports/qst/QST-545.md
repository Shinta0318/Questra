# QST-545 Budgeted and Source-Bound Grounded Search

Status: In Progress / local_partial

## Finding

Arc Chat and Mission Research used a separate `groundedMissionSearch` request that bypassed QST-342's atomic model and Google Search query budgets. Mission Research had a non-atomic hourly request count, but it was not a provider-cost admission gate.

## Local implementation

- Grounded search now requires a validated user ID and calls the shared Interactions adapter with the Google Search tool. The adapter reserves model and grounding-query budgets before invoking Gemini, then records the provider receipt and settles actual tokens and verified query count.
- Arc Chat supplies its authenticated user ID; Mission Research supplies the owner-checked user's ID. The latter retains its cache and existing rate-limit behavior.
- The response uses structured output. Search text is only returned as grounded guidance when the provider included validated HTTPS source metadata; absent sources result in no grounded answer. Existing source sanitization still excludes local/private endpoints.
- The change is local only. The hosted function, migration, model/tool combination, source quality, and user-facing citation display have not been verified on the same candidate SHA.

## Verification

- `node --test supabase/functions/_shared/grounded_search_budget.test.mjs`: covers invalid user, budget denial before model call, query reserve before Gemini, actual token/query settlement, and source metadata. No real provider or database call is made.
- Google's [Gemini 3 developer guide](https://ai.google.dev/gemini-api/docs/gemini-3) documents combining structured output with Google Search in Interactions; this does not replace a live Questra integration test. Checked 2026-10-07.
