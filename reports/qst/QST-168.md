# QST-168 Input Validation Hardening

**Status: Done**

## Goal

認証、Quest、Mission、Trail、オンボーディング、フィードバック、Arc入力の検証を共通化し、未入力、形式不正、過大入力を送信前に分かりやすく通知できる状態にする。

## Implementation

- `InputLimits` と `InputValidators` を追加し、文字数上限と日本語エラー文を一元管理した。
- メールアドレスは空白、`@`、ローカル部、ドメインラベルの実用的な体系チェックを行う。
- 電話番号は国番号付き表記、空白、ハイフン、括弧を許容し、正規化後7〜15桁を検証する。現時点で電話番号入力欄はないため、将来のProfile/Auth拡張向け基盤として提供する。
- ログインは既存アカウント互換性を優先し、必須・最大長のみ検証する。新規登録は8〜72文字かつ英字と数字を含むことを検証する。
- Quest、Mission、Trail、Reflection、オンボーディング、Betaフィードバックに必須・任意・最大長検証を適用した。
- Arc Chatは空入力を拒否し、1,200文字を上限とした。UIだけでなくSupabase送信直前にもtrimと上限適用を行う。
- ArcからのQuest相談は1,000文字、生成されたQuest候補名は100文字を上限とした。

## Review Notes

- 正規表現だけでメールの実在性は確認できないため、実運用ではSupabase Authの確認メールを最終確認とする。
