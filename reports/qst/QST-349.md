# QST-349 Unified Durable Mutation and Conflict Recovery

## Status

Implemented locally as a shared contract.

## Summary

Added a shared durable mutation model for Quest, Mission, Task, Trail, and Media
mutations. The existing Task offline queue remains the concrete implementation,
but its offline failure detection now uses the shared core contract so future
domains can adopt the same idempotency, owner boundary, retry, expiration, and
conflict semantics.

## Changed Files

- `apps/mobile/lib/core/persistence/durable_mutation.dart`
- `apps/mobile/lib/features/task/task_mutation_state.dart`
- `apps/mobile/test/qst_349_durable_mutation_test.dart`

## Acceptance Notes

- Durable mutation phases include idle, saving, saved, failed, offline pending,
  and conflict.
- Mutation intents carry owner ID, domain, entity ID, operation, idempotency
  key, expected version, attempts, and queue timestamp.
- Queue policy rejects owner mismatch, short idempotency keys, excessive
  attempts, and expired entries.
- Conflict state preserves the remote version and requires user choice.
- Task mutation state now uses the shared offline failure classifier.
