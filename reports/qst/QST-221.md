# QST-221 Adaptive Quest Planning Engine V3

Status: Completed

## Product Decision

Questraはカテゴリ別テンプレートからMissionを流し込まない。Quest固有の成功条件、制約、現在地を理解し、最小十分な航路を設計する。

## Implementation Sequence

1. QST-222でSuccess Contractと仮定を構造化する。
2. QST-221で固定Mission数とテンプレート生成依存を撤去する。
3. QST-223/224で多段評価とMissionの具体性契約を導入する。
4. QST-231で200件のペルソナ差分評価をリリースゲート化する。

## Progress

- Arc Quest GuideのGeminiプロンプトから、テンプレートのMission見出し・順序を渡す処理を除去した。
- テンプレートは安全性と品質確認の観点だけを渡す`quality_viewpoint`へ変更した。
- ローカルフォールバックはQuestのタイトル、説明、期限から4件の最小航路を構成し、カテゴリ別テンプレートのMission本文を使用しない。

- Flutter側の未接続時フォールバックも、カテゴリ固定Missionではなく4件の安全な確認航路へ変更した。
- 200件CorpusでMission契約、重複、Quest名流用を検証した。

Completion evidence: 200件の同意済みContext Corpusと全Flutterテストを通過した。実Provider probeは無料枠制限によりfallbackとなり、QST-231のRelease Gateが昇格を停止する。

## Compatibility Boundary

Existing Quest、Mission、Routeは読み取り可能なまま維持する。新しい計画属性はバージョン付きで追加し、ユーザーの明示承認なしに既存航路を置き換えない。
