## Observed failure

The connected preview reached `/legal-consent` after authentication, but showed an unrelated generic authentication error. The Beta Dashboard was queried read-only: `legal_acceptances`, `legal_release_policies`, and `accept_current_legal_policy(text,text,text,text,text,boolean,timestamptz)` were all absent. The current app treated any failed acceptance lookup as "not accepted", so a missing table appeared as a fresh consent request. The screen also displayed an error carried over from another auth action. No password, token, email address, or account ID is retained here.

The latest applied Beta migration observed in QST-575 was `202608080006`; the consent migration is `202608180001`, with seven unrelated migrations between them. Applying only the consent migration out of order is not a safe substitute for a reviewed incremental deployment.

## Local change

- Preserve fail-closed consent enforcement: a confirmed session alone never bypasses the legal gate.
- Distinguish a readable "no current acceptance" result from an unavailable acceptance lookup. The latter shows a retryable service message, not a fresh consent form.
- Show only errors from the legal consent action on the consent screen; use consent-specific wording instead of an authentication error.
- After the acceptance RPC, read the current server-side record again before marking the profile accepted. An already accepted profile continues to route away from the consent screen.
- Before signup creates an Auth user, read the active server release policy and require the same version, region, and minimum age. If the Beta schema is missing, show a registration-readiness message and do not create another account that will become trapped at the gate.
- For an existing account with a complete current signup-consent claim but no immutable server record, offer one concise explicit confirmation with an option to review the full checklist. The claim changes the presentation only; it never grants access. Accounts without that claim still see the full checklist.
- The isolated incremental migration workflow now checks the two legal tables and acceptance RPC as well as authentication RPCs.
- A later UI follow-up labels an unavailable server lookup as a connection check, explicitly says previously consenting users need not agree again, and shows no consent checkboxes in that state. Route tests cover a server-recorded signup acceptance bypassing the consent page and ensure signup metadata alone cannot bypass a missing server record.
